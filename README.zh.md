# ADI — Agent–Device Interface

**能在断网时继续工作的本地优先智能体运行时。** 云是可选的加速器，永远不是地基。

> `pre-alpha`：骨架已经在 macOS 上真跑，公开 API 还没冻结。

---

## 为什么做这个

现在你能用到的助手，几乎都在网络断掉的那一刻失效——模型、声音、记忆、界面，全都租自同一家供应商。

ADI 反着建：**每一层都有本地退路，拔掉任何一层，系统仍然活着。**

这个约束带来的不是"功能更多"，而是几条不同的性质：

| 性质 | 实际表现 |
|---|---|
| 可降级 | 语音、模型、界面各自有本地退路，而不是直接报错 |
| 可替换 | 模型、声线、供应商是可换零件，不是身份 |
| 私有 | 记忆留在这台机器上，默认不上传 |
| 认得设备 | 能对着真实物体讲解，而不只是聊天 |
| 有分寸 | 主动开口由证据决定，不由计时器决定 |

## 结构

```
adi-app      macOS 外壳（AppKit + WKWebView）      AGPL-3.0
adi-runtime  编排、退路链、通道、主动开口闸门      AGPL-3.0
adi-sdk      Python / TypeScript 客户端            Apache-2.0
adi-docs     文档站点（GitHub Pages）              CC BY 4.0
```

运行时在本机用普通 HTTP + SSE，任何能发 JSON 的东西都能驱动它：桌面外壳、手机 App、
定时任务，或者另一个智能体。

## 四条设计纪律

1. **不依赖云。** 每个能力都要有本地实现路径；调用云是性能选择，绝不是正确性依赖。
2. **每一层都可降级。** 神经语音不在，就用系统语音；远端脑不在，就用本地脑——绝不哑巴。
3. **名字不是身份。** 换模型、换声线不能改变"它是谁"；身份在记忆和权限里，不在供应商字符串里。
4. **只有能改变你下一步动作的话才主动说。** 主动开口必须引用状态接口里的真实数字，否则不说。

## 许可证

| 路径 | 许可证 | 理由 |
|---|---|---|
| `adi-sdk/` | Apache-2.0 | 允许商用 |
| `adi-runtime/`、`adi-app/` | AGPL-3.0 | 改进必须回流 |
| `adi-docs/` | CC BY 4.0 | 文档要能传播 |

## 参与

现在最有用的贡献是**一个你能证明的降级**：挑一层，把它的电源拔掉，证明系统照样答话。
带上命令和输出开 issue。可复现的降级报告，比功能请求值钱。
